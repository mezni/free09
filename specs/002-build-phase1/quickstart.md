# Quickstart — build-phase1

## Purpose
A validation guide that proves the build phase 1 feature works end-to-end without
introducing runtime network endpoints or database objects (BR-011).

## Prerequisites
- Python 3.13+ installed
- `uv` 0.12.15+ installed
- `make` installed
- `docker` available (for PostgreSQL)

## Validation Scenarios

### Scenario 1: Fresh Clone to Verified State
**Command**: 
```bash
git clone <repository>
cd telco-platform
make setup
```

**Expected Outcome**:
- Repository skeleton created (services/, libs/, ci/, tests/, deploy/compose/)
- pyproject.toml, Makefile, uv.lock generated
- .python-version pins 3.13
- .gitignore updated with Phase 0 exclusions
- uv.lock generated and verified

**Success Criteria**: SC-001 (fresh clone to verified state ≤ 30 minutes)

### Scenario 2: Run Fast Checks
**Command**: 
```bash
make test
```

**Expected Outcome**:
- nox fast-checks suite runs
- Format, lint, lockfile, governance, file-coverage, typecheck, test, secret-scan,
  dependency-audit checks execute
- Exit code 0 if all PASS, 1 if any FAIL, 2 if COULD NOT RUN, 3 if INTERNAL ERROR

**Success Criteria**: SC-005 (fast lane ≤ 2 minutes)

### Scenario 3: Start PostgreSQL and Verify
**Command**: 
```bash
docker compose -f deploy/compose/compose.yaml up -d
```

**Expected Outcome**:
- PostgreSQL 16.15-alpine container starts
- Health check passes within 30 seconds
- Container named postgres-telco

**Success Criteria**: PostgreSQL running and healthy

### Scenario 4: Full Verification
**Command**: 
```bash
make local-verification-command-runs-all-required-checks
```

**Expected Outcome**:
- All required checks run (format, lint, lockfile, governance, file-coverage,
  typecheck, test, secret-scan, dependency-audit)
- All checks report PASS (exit code 0)

**Success Criteria**: All SC met (SC-001 through SC-005)

## Notes
- BR-011: No runtime network endpoint and no database object introduced by Phase 0
- BR-012: Tooling does not change the Python FastAPI on PostgreSQL baseline
- All artifacts generated by /speckit.tasks or /speckit.specify
- Implementation details belong in tasks.md and the implementation phase
- This is a validation guide only - no implementation code, model bodies,
  service controllers, or complete test suites included

## Quick Start
```bash
git clone <repository>
cd telco-platform
make setup
make test
docker compose -f deploy/compose/compose.yaml up -d
make local-verification-command-runs-all-required-checks
```
